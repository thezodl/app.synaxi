# Synaxi Web: project notes for agents

Read this before changing anything. The plan and decisions are in [docs/PLAN.md](docs/PLAN.md); current status
and open items are in [docs/STATUS.md](docs/STATUS.md). Keep both up to date when you finish a piece of work.

## What this is

A simple, online-first, desktop-first PWA RSS reader for one user, on Next.js + Vercel (Hobby) + Neon (Free) +
Auth0. It's the web sibling of the Expo app in `../app.synaxi.mobile`, whose `src/core` was copied here. Feeds
come from an OPML import, because the Feedly API is Enterprise-only, so don't suggest it.

## Hard rules

- **Feed URLs are secrets.** They are stored encrypted (`url_enc`) and are never logged, returned by the API
  (apart from OPML export), included in error messages, fixtures, commits or PR text. Don't ask the user to
  paste one.
- **Every `/api/*` route verifies a Bearer access token** (`requireUser`), except cron, which checks
  `CRON_SECRET`. A session cookie alone must not authorise API access.
- **No read state.** Bookmarks are the only "read" concept. Don't add unread counts or an Unread view.
- `src/core/` is **pure TypeScript** with no Next/React imports, and is unit-tested with `bun test`.
- Migrations are generated by drizzle-kit and are **append-only**. Never edit a shipped migration.
- **Local dev uses the prod database** (the user's choice; one Neon branch). So:
  - `bun run db:migrate:local` changes prod immediately. Only **expand-first** migrations (add columns/tables,
    no drops/renames of anything deployed code still uses), and say so in the PR.
  - Test data written while developing is real data. Use public feeds and delete them afterwards.
  - `FEED_URL_KEY` must be identical in Vercel Development and Production.
- Stay within the free tiers: Vercel Hobby cron runs at most once a day, and Neon Free gives 1 GB.
- Use **bun** (`bun add`, `bun run`, `bunx`), not npm/npx.
- **Next 16:** request interception lives in `src/proxy.ts` (not `middleware.ts`). `cacheComponents` is on:
  GET route handlers are prerendered unless they read request data. Never swallow Next's internal errors in a
  `catch`; call `unstable_rethrow(e)` first (see `withUser`). Read `node_modules/next/dist/docs/` before
  using an API you haven't checked.
- `src/server/*` modules import `server-only`, which can't load under `bun test`. Keep testable logic in
  modules without Next imports (e.g. `jwt.ts`), and keep `server-only` out of anything `proxy.ts` imports.

## Verify before declaring done

```bash
bun run check && bun run build
```

## Environment quirks

- The dev machine is **ARM64 WSL2**.
- The local agent shell has **no GitHub credentials**, so the user runs `git push`. Only commit or push when asked.
- Line endings are LF. CRLF-only diffs are noise from Windows; tell the user rather than discarding them.
